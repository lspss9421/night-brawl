# PRD v1.0：2D 網頁連線格鬥小遊戲

> 狀態：**定稿**（2026-11-10）。標註【預設，可改】的項目已採用目前數值，之後可在測試中調整。角色細節見 [characters/](characters/)。

## Context（為什麼做）

做一款打開網址就能玩的 2D 1v1 格鬥遊戲，朋友之間分享房間連結就能線上對打。角色美術全部由你用 AI 生成並客製化，所以除了遊戲本身，還要有一套「把 AI 生成的圖變成可玩角色」的工具流程。

## 1. 已確認決策

| 項目 | 決定 |
|---|---|
| 動畫做法 | 逐格 Sprite Sheet，**像素風 Q 版** |
| 美術來源 | 你用 AI 生成；第一位角色 Sawa 的參考圖已提供 |
| 操作 | 4 個攻擊鍵（輕/重拳、輕/重腳）+ 特殊鍵（方向 + 特殊）+ 挑釁鍵 |
| 必殺技 | 能量滿格施放，有演出畫面 |
| 連線 | Rollback 回滾同步，P2P（WebRTC） |
| 配對 | 房間連結 / 房號，無帳號系統 |
| 平台 | 只有桌機瀏覽器（鍵盤） |
| MVP 內容 | 2 位角色、能量條 + 必殺技、單人模式 |
| 判定框編輯工具 | 第一版就做 |

## 2. 產品目標與非目標

- **目標**
  1. 免安裝，Chrome / Edge / Firefox / Safari 最新版可玩。
  2. 延遲 ≤ 100ms 時無明顯卡頓，畫面穩定 60 FPS。
  3. 新增角色只需放素材 + 用編輯工具設定，不改核心程式碼。
- **非目標（MVP 不做）**：帳號、排名、隨機配對、觀戰、手機觸控、搖桿、3 人以上。

## 3. 核心玩法

### 3.1 對戰規則 【預設，可改】
- 1v1，三戰兩勝。回合時間可在主選單切換：99 秒（時間到血多者勝）或無限（預設，方便測試）；線上對戰以房主的設定為準。
- 單一平面場地，左右有邊界，鏡頭跟隨兩人。

### 3.2 操作（鍵盤）【預設，可改】
| 動作 | 按鍵 |
|---|---|
| 移動 / 蹲 / 跳 | WASD |
| 輕拳 / 重拳 | U / I |
| 輕腳 / 重腳 | J / K |
| 特殊技 | L（每位角色一招：Sawa 愛心波動、Mio 鞭擊） |
| 必殺技 | 能量滿時 L + K 同按 |
| 投技 | 靠近時 → + I + K 同按 |
| 鬥氣 | O（P2 用 /）：按住 = 檔架；防禦中按 = 鬥氣反擊 |
| 拆投 | 被抓住的瞬間也按 → + I + K |
| 挑釁 | T（純表演，無遊戲效果） |
| 防禦 | 按住後方向（傳統格鬥做法） |
| 衝刺 / 後撤 | 前前 / 後後 |

- 支援自訂按鍵。
- 不使用 236 / 623 這類搓招指令，降低上手門檻。

### 3.3 戰鬥系統（參考 SF6 的攻防設計，2026-11-12 改版）

**攻防三角**：攻擊克制投技（投技第 5 格才抓到，輕攻擊比它快）→ 投技克制防禦（防禦中、檔架中都會被抓）→ 防禦克制攻擊（擋下後可趁對手收招反擊）。

**兩條資源槽**
| | 鬥氣槽 | 能量槽 |
|---|---|---|
| 大小 | 6 格，每回合開局全滿 | 1 條，保留到下一回合 |
| 用途 | 特殊技（每次 1 格）、檔架、鬥氣反擊（2 格） | 必殺技（L+K） |
| 回復 | 隨時間（約 20 秒回滿；防禦／受擊／檔架中不回）、一般攻擊打中（輕 1/4 格、重 1/2 格）、檔架成功（1/2 格） | 攻擊、被打、被防都會累積 |

**燃盡**：鬥氣用光進入燃盡，直到回滿為止；燃盡期間回復速度加倍（約 10 秒回滿）。燃盡中不能用特殊技、檔架、鬥氣反擊；防禦時被削血（約傷害的 1/4）、防禦硬直多 4 格。角色變暗、鬥氣槽變灰閃爍。

**檔架**：按住鬥氣鍵。按下扣半格、按住持續消耗；擋得住所有打擊（上中下段、空中、飛行道具、必殺技），擋下回半格；擋不住投技，檔架中被抓傷害 1.5 倍。最短持續 12 格，放開後有 12 格收招。
**完美檔架**：檔架開始的前 2 格內擋到 → 自己馬上能動，攻擊方僵直 30 格（顯示「破綻」）。

**鬥氣反擊**：防禦中按鬥氣鍵，扣 2 格；出招到攻擊結束前無敵，傷害小且打不死人，主要把對手推開、脫離壓制。

**投技**：→ + 重拳 + 重腳。第 5 格才抓到；抓住後轉身，把對手從前面甩到身後再往反方向丟出去約半個舞台遠（整段約 1 秒：抓住 14 格 → 轉身 22 格 → 第 36 格丟出 → 收招到第 62 格；投技方結束時面向對手），對手落地時才扣血、倒地再爬起來（雙方左右位置互換）；抓空收招很大；被抓後 10 格內也按投技 = 拆投（雙方彈開不扣血）；雙方同時投也會自動拆投。不能抓空中、受擊中、防禦中的對手。

**其他**
- 狀態：待機、移動、前搖、攻擊判定、後搖、受擊硬直、防禦硬直、檔架、破綻、倒地、起身。
- 判定框：推擠框、受擊框（**跟著動畫每一格變化**，出招時伸出的手腳也會被打）、攻擊框（只在攻擊判定格有效）。
- 取消：普通技打中或被防時，可以取消成特殊技或必殺技。
- 輸入緩衝：5 格。
- 打擊感：頓幀 3～8 格；重攻擊、擊倒、KO、必殺技、完美檔架時畫面輕微震動；命中火花黃橘色、防禦藍色、檔架水藍色、完美檔架白色、鬥氣反擊金色、拆投白色 ✕。
- 音效：先預留事件觸發點（命中輕／重、防禦、檔架、完美檔架、投技、拆投、鬥氣反擊、燃盡），尚未加入聲音。
- 除錯模式（F1）：判定框、每位角色的狀態與第幾格、硬直、無敵、鬥氣，以及上一擊的有利／不利格數。
- 固定 60 tick/秒的邏輯更新，邏輯完全可決定性（rollback 的前提）。
- 不做：霸體重擊、取消衝刺（Drive Impact / Drive Rush）。

### 3.4 單人模式
- **訓練模式**：假人站樁，顯示判定框、傷害、影格資訊（也是你調角色手感的地方）。
- **打電腦**：簡單規則式 AI（接近、出招、隨機防禦），分 2–3 種難度。

## 4. 角色與美術管線（本專案的關鍵）

### 4.1 角色
| 角色 | 定位 | 狀態 |
|---|---|---|
| 佐波 Sawa | 可愛甜美；速度型；必殺技是拿麥克風唱歌的全畫面音波（可被格擋） | 設定完成，見 [characters/sawa/sawa.md](characters/sawa/sawa.md) |
| Mio | 撲克臉、慵懶；一般型；特殊技是長距離鞭擊；必殺技變身成原創黃色小恐龍 10 秒（攻擊 ×1.3、移速 ×0.7） | 設定完成，見 [characters/mio/mio.md](characters/mio/mio.md) |

- 出場、勝利、戰敗、挑釁都有專屬動作；對話框由遊戲 UI 繪製（不畫進角色圖）。

### 4.2 每位角色的動畫清單
Sawa 約 **170 格**；Mio 約 **215 格**（含恐龍形態約 46 格）。不含特效，完整清單見各角色設定書。
美術分兩批交付：先做約 90 格「能打起來的最小集合」，其餘第二批補齊。

### 4.3 AI 生圖 → 可玩角色的流程
AI 生圖最大的難題是**每一格之間角色長相、比例、位置要一致**，所以流程設計成：

1. **角色基準圖**：以你上傳的人物圖為準，先產出正面設定圖（三視圖或 T-pose）。
2. **逐動作生成**：每個動作用基準圖當參考產生關鍵格（AI 圖生圖 / 動作控制），必要時補中間格。
3. **去背**：統一處理成透明背景 PNG。
4. **匯入編輯工具**（瀏覽器內，MVP 內建）：
   - 拖入一組影格圖 → 自動排成動畫
   - 設定**腳底錨點**對齊（解決 AI 圖每張位置不同的問題）
   - 統一縮放比例、預覽播放速度
   - 框選 hurtbox / hitbox / pushbox，設定傷害、硬直、取消窗口
   - 匯出成 Sprite Sheet（打包好的大圖）+ 角色設定 JSON
5. **遊戲讀取**：遊戲只讀「Sprite Sheet + JSON」，換角色不用改程式。

### 4.4 素材規格 【預設，可改】
- 遊戲解析度基準 1280×720。
- 每格畫布 128×128 像素，角色本體約 96–110 像素高；遊戲中整數放大 2 倍並保持像素銳利（角色約 210 像素高，在 1280×720 畫面中比例合適）。
- 透明背景（或純綠 #00FF00 方便去背）、一律面朝右、腳底踩在同一條水平線。
- 角色與特效分開輸出。
- 參考圖本身是「設定圖」不是遊戲素材（每個動作格數太少、大小位置不一、背景與文字混在一起），需依規格逐動作重新生成。
- 開發初期用色塊暫代角色，美術進來後直接替換。

### 4.5 其他素材 【預設，可改】
- 場景 1–2 張（也可 AI 生成）、UI（血條、能量條、計時、角色選擇）。
- 音效與音樂：先用免版稅素材，之後可換。

## 5. 連線對戰

- **架構**：Rollback Netcode，雙方 P2P 透過 WebRTC DataChannel 傳輸入。
- **配對伺服器**：Node.js + WebSocket，只負責開房、交換連線資訊（signaling）。
- **NAT 穿透**：STUN；連不上時走 TURN 中繼。
- **流程**：A 建房 → 取得連結/房號 → B 開連結加入 → 雙方選角 → 開打 → 結束可再戰。
- **斷線**：等待 10 秒重連，超時判對方勝。
- **輔助**：顯示延遲（ping）、可調輸入延遲幀數（0–3）。
- **防作弊**：MVP 只做基本的狀態校驗（checksum 不一致時提示 desync），不做完整防作弊。

## 6. 技術架構（建議）

| 層 | 選擇 |
|---|---|
| 語言 | TypeScript |
| 渲染 | PixiJS（WebGL） |
| 遊戲邏輯 | 自寫、固定影格、與渲染分離、可序列化（rollback 需存/讀狀態） |
| 連線 | WebRTC DataChannel + 自寫 rollback 核心 |
| 配對伺服器 | Node.js + WebSocket |
| 編輯工具 | 同一專案內的另一個頁面（/editor） |
| 建置 | Vite，monorepo（game / editor / server / shared） |
| 部署 | 前端 Cloudflare Pages 或 Vercel；伺服器 Fly.io 或 Render；TURN 用 Cloudflare 或 Metered 【預設，可改】 |

## 7. 畫面流程

標題 → [線上對戰：建房/加入 → 角色選擇] / [單人：訓練或打電腦 → 角色選擇] → 對戰 → 結算 → 再戰 / 回標題。另有「按鍵設定」與「角色編輯器」入口。

## 8. 里程碑

1. **M1 本機原型**：色塊角色、同一台電腦兩人對打；移動、攻擊、判定、防禦、血條、回合。手感先調好。
2. **M2 判定框編輯工具**：匯入影格、錨點對齊、框選判定、匯出 Sprite Sheet + JSON。
3. **M3 第一位角色**：用你的 AI 圖跑完整流程，接入遊戲；訓練模式。
4. **M4 連線**：配對伺服器 + WebRTC + rollback，兩台電腦可對打。
5. **M5 內容補完**：第二位角色、能量條與必殺技、電腦 AI、場景、UI、音效。
6. **M6 上線**：部署、跨網路延遲測試、修 bug。

## 9. 成功指標

- 兩台不同網路的電腦可穩定打完三戰兩勝，無 desync。
- 模擬 100ms 延遲時操作仍順暢；60 FPS 穩定。
- 用編輯工具從零接入一位新角色，不需動程式碼。

## 10. 風險與對策

| 風險 | 對策 |
|---|---|
| AI 生圖每格不一致、動作不連貫 | 先用基準圖鎖定角色；編輯工具提供錨點對齊與逐格替換；必要時減少格數、用補間/殘影掩飾 |
| 美術量大（每角色 120–180 張） | M1–M2 先用色塊開發，不讓美術卡住程式進度；先做最少可玩動作集 |
| Rollback 需要邏輯完全可決定 | 邏輯不用浮點亂數與時間函式；加 desync 檢查與自動化測試 |
| 部分網路 WebRTC 連不上 | TURN 中繼備援 |
